# Species profiles

Profiles are declarative YAML documents. The schema is `src/wildlife_radar/profiles/schema.py`; inheritance is resolved by `ProfileLibrary`.

- `templates/` holds `base`, the guild templates and `groups/` (`kind: template`). The group templates (`group/birds`, `group/fishes`, ...) give generated drafts default methods until a reviewer assigns a guild.
- `species/` holds species profiles (`kind: species`). They `extend` one or more templates and override only what differs.

## Inheritance rules

- Mappings merge recursively.
- Lists and scalars are replaced.
- Two lists accumulate instead of being replaced: `policy.always_suppress` and `guilds`.
- A few fields are never inherited: `id`, `kind`, `extends`, `scientific_name`, `common_name`, `status` and `notes`.

## Status of these profiles

All current profiles are hand-written `draft`s. They seed the framework's five design-validation species and will be regenerated by the profile-generation pipeline (`docs/design/framework.md` §4.3).

- Values are **weak priors and hypotheses**, not facts.
- Every non-obvious value carries `provenance` pointing to the research notes. Confidence is set low where the research marked a claim UNVERIFIED.
- Signals marked `hypothesis: true` are candidates that the evaluation harness must test by ablation before they are trusted.
- Cross-database IDs (`crosswalk`) are deliberately left out of hand-written profiles. They are resolved and verified by the pipeline, never typed by hand.

## Generated drafts

`wildlife-radar profilegen generate` writes drafts to `data/profiles/generated/` (git-ignored, because they are derived from third-party data). Each draft has:

- `crosswalk`: GBIF, iNaturalist (verified against iNaturalist, following renamed concepts), Wikidata, NCBI, ITIS, WoRMS, Catalogue of Life and IUCN ids.
- `traits` with **per-field `provenance`**: source, method (import / computed / extracted / ...), confidence, license, and where to verify the value. Extracted values cite a Wikipedia revision and character range, never copied sentences.
- `generation`: inherited licenses (license taint), whether a fully open variant is possible, conflicts between sources, notes, and a **review queue** ranked by uncertainty × impact.
- No `policy`: tiers come only from status providers and human overrides.

To review and promote:

```bash
uv run wildlife-radar profilegen review puma-concolor
```

```bash
uv run wildlife-radar profilegen promote puma-concolor --reviewer "Your Name" --lock traits.activity_pattern --reject traits.home_range_km2
```

Promotion copies the draft into `species/`, marks it `reviewed` and adds the checked fields to `locked`. Regeneration never changes locked fields, and a rejected field stays absent. Promotion refuses to overwrite a hand-curated profile unless you pass `--replace-curated`.

`ProfileLibrary(extra_dirs=...)` can load draft directories. A curated profile shadows a draft with the same id.

## Policy

- A profile can **raise** a taxon's tier (`default_tier`, seasonal `windows`).
- A regional entry that **lowers** the tier below the default is ignored unless it has:
  - two distinct `approved_by` reviewers,
  - a `note` explaining why,
  - a future `review_by` date.

  See `wildlife_radar.policy.resolve`.
